# 低分检索自救手册

面向资深 RAG 工程师的排查 playbook。触发条件：rerank 精排后 top1 相关性分数低于阈值。

**资源**：本 skill 附带 `scripts/extract_terms.py`——用 jieba 从查询中抽取关键术语，供术语对齐步骤使用（调用方已负责执行，结果以关键词列表形式传入）。

## 策略（推荐顺序，可依据尝试历史灵活调整）

1. **改写诊断（rewrite-check）**：检查改写后的查询是否丢失了原始问题中的关键术语、是否被错误地指代消解。修正方式是直接给出一个更忠实的查询，而不是重写整个改写链路。
2. **术语对齐（term-align）**：用户常用口语词，知识库用术语。参考以下已知知识库术语，将口语表达替换为库内术语后再检索：
   - 倒排索引 / 关键词检索 → `bm25`
   - 语义检索 / 向量搜索 → `vector_search`
   - 精排 / 重排序 → `rerank`
   - 多路召回融合 → `rrf`
   - 多轮追问改写 → `query_rewrite`
   - LangChain / LangGraph → `langchain`
3. **HyDE（hyde）**：先根据问题生成一段假设性的答案（60~100 字），用这段假设答案作为查询去检索——假设答案与知识库文档的向量空间更接近。
4. **子查询拆分（decompose）**：把复杂问题拆成 2~3 个独立的简单子查询，分别检索后取分数最高者。

## 执行约束

- 每一轮只选**一个**策略，给出 1~2 个候选查询，调用方会用 MCP 检索工具（hybrid_search + rerank）逐条重检并回报 top1 分数。
- 每次重检后 top1 仍低于阈值，才进入下一轮；**已尝试过的策略不要重复**（除非换完全不同的查询角度）。
- 连续 3 轮（或手册策略全部耗尽）仍未达标，输出 `策略: GIVE_UP`，由调用方升级人工介入。

## 输出格式（严格遵守）

```
策略: <策略名，如 hyde / term-align / GIVE_UP>
查询:
- <候选查询1>
- <候选查询2>
```

只输出以上结构，不要输出解释、markdown 代码块或额外内容。
